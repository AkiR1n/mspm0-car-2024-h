# 自动行驶小车 H 题记录与阶段计划

本文档记录 H 题规则、工程约束、路线目标，以及当前阶段要先完成的基础模块。

当前优先级不是一次性完成全部比赛策略，而是先把两个最基础能力做扎实：

1. 无循迹直线跑：不依赖黑线闭环，使用速度环、编码器和 IMU 保持直线前进。
2. 有线循迹：使用 7 路循迹传感器沿黑线稳定行驶。

## 1. 题目目标

设计一辆基于 TI MSPM0 系列 MCU 的轮式自动行驶小车，在指定白色场地中按照规定路线自动行驶、经过关键点声光提示，并在终点停车。

核心要求：

- 主控芯片必须使用 TI MSPM0 系列 MCU。
- 小车必须自主行驶，测试过程中不得遥控、不得人为干预。
- 禁止使用摄像头。
- 禁止使用场地外环境或额外设备导航。
- 车载电池供电，测试过程中不得更换电池。
- 小车只能前进，不得后退。

小车尺寸限制：

- 长度不超过 25 cm
- 宽度不超过 15 cm
- 高度不超过 15 cm
- 轮式小车
- 禁止履带车、麦克纳姆轮

## 2. 场地与路线

场地：

- 最小尺寸：220 cm x 120 cm
- 材质：白色哑光喷绘布
- 场地上只有两条黑色对称半圆弧线
- 圆弧半径：40 cm
- 线宽：约 1.8 cm
- 场地上不得添加 A/B/C/D 字符或其他标记

关键点：

- A：左侧半圆弧上端点
- D：左侧半圆弧下端点
- B：右侧半圆弧上端点
- C：右侧半圆弧下端点

几何关系：

- A 到 D 或 B 到 C 的垂直距离：80 cm
- A 到 B 或 D 到 C 的水平距离：约 100 cm
- A -> B：上方直线路径
- C -> D：下方直线路径
- D -> A：左侧半圆弧路径
- B -> C：右侧半圆弧路径

## 3. 测试通用规则

- 起点为 A 点。
- 起始方向由参赛队自定。
- 启动时需要声光提示。
- 经过 A、B、C、D 点时需要声光提示。
- 停车时需要声光提示。
- 启动、停车、经过关键点时，小车地面投影必须覆盖对应圆弧顶点。
- 小车在圆弧上行驶时，地面投影必须保持在圆弧线上。
- 圆弧行驶中一旦脱离圆弧线，该测试项目失败。

## 4. 任务列表

### 任务 1：A -> B

- 路线：A -> B
- 要求：到达 B 点停车，并声光提示。
- 限时：不超过 15 秒。
- 分值：20 分。

### 任务 2：A -> B -> C -> D -> A

- A -> B：直线。
- B -> C：右侧半圆弧。
- C -> D：直线。
- D -> A：左侧半圆弧。
- 要求：每经过一个点声光提示一次，最后在 A 点停车。
- 限时：不超过 30 秒。
- 分值：20 分。

### 任务 3：A -> C -> B -> D -> A

- A -> C：直线或斜向路径。
- C -> B：右侧半圆弧。
- B -> D：直线或斜向路径。
- D -> A：左侧半圆弧。
- 要求：每经过一个点声光提示一次，最后在 A 点停车。
- 限时：不超过 40 秒。
- 分值：30 分。

### 任务 4：任务 3 连续 4 圈

- 路线：按任务 3 路线连续行驶 4 圈后停车。
- 目标：用时越少越好。
- 分值：30 分。

## 5. 设计报告要求

设计报告分值 20 分，至少覆盖：

- 小车自动行驶系统方案
- 自动行驶误差分析
- 轨迹控制方法
- 控制电路设计
- 程序流程设计
- 测试方案
- 测试数据与结果分析

## 6. 当前工程基础

当前工程已有基础能力：

- MSPM0G3507 + FreeRTOS 主线工程。
- 双路编码器测速。
- 左右轮速度闭环。
- `Twist(v, w)` 到左右轮速度目标的控制链路。
- 7 路循迹传感器，输出 `line_bits`、`line_detected`、`line_position`。
- IMU 已接入，常规串口状态行包含 `imu=(ready,stable)`、`yaw`、`gz`、`up` 摘要。
- 上位机 Dashboard 可同时观察速度、IMU、循迹和串口日志。

当前要避免的风险：

- 不要过早把完整赛题状态机、IMU 接管、点位判定、圈数统计全部混在一起调。
- 先分别证明直线能力和循迹能力，再组合成赛题路线。

## 7. 第一阶段目标

第一阶段只完成两个基础模块。

### 7.1 无循迹直线跑

这里的“无循迹”指不依赖黑线传感器闭环，不是无线遥控。小车仍然必须自主运行。

目标：

- 小车从 A 点出发，沿预定直线方向前进。
- 使用编码器控制行驶距离。
- 使用 IMU yaw 做直线航向保持。
- 到达目标距离后停车并声光提示。

建议先做两档：

1. 短距离直线：30 cm 到 50 cm，用于确认速度环、编码器距离积分、停车动作。
2. A -> B 直线：约 100 cm，用于覆盖任务 1 的基础能力。

控制策略：

- `v_mps` 作为前进速度命令。
- `w_radps` 由航向误差 PID 输出。
- 目标航向在启动时锁定为当前 yaw。
- 距离由左右轮编码器积分估计，先用左右轮平均距离。
- 接近终点时降速，减少过冲。

第一版验收标准：

- 起步不明显偏转。
- 100 cm 直线终点横向偏差可控。
- 停车不后退。
- 串口能记录目标距离、当前距离、yaw、heading error、速度。

当前固件调试入口：

```text
straight                 # 默认 0.50 m, 0.25 m/s
straight,0.30            # 直线 0.30 m, 默认 0.25 m/s
straight,1.00,0.35       # 直线 1.00 m, 0.35 m/s
stop                     # 手动停止
```

串口状态行关键字段：

- `mode=STRAIGHT`
- `state=GAP`
- `dist=<当前距离>/<目标距离>`
- `hold=<锁定航向>`
- `err=<航向误差>`
- `vw=(v,w)`

暂不要求：

- 自动识别 B 点。
- 自动切入圆弧。
- 多段路线编排。

### 7.2 有线循迹

目标：

- 小车沿黑线稳定前进。
- 能在左右半圆弧上保持车体投影覆盖圆弧线。
- 丢线时能低速回找。
- 弯道自动降速。

控制策略：

- 使用 7 路循迹传感器。
- `line_position` 输入线位置 PID，输出 `w_radps`。
- 根据偏差和位型调度前进速度 `v_mps`。
- `line_detected == 0` 时进入丢线回找状态。

第一版状态：

- `TRACK`：正常循迹。
- `LOST_LEFT`：线从左侧丢失，低速向左回找。
- `LOST_RIGHT`：线从右侧丢失，低速向右回找。

第一版验收标准：

- 低速直线黑线可稳定跟随。
- 单侧半圆弧低速可稳定跟随。
- 丢线后不会高速冲出场地。
- 串口能记录 `line_bits`、`line_position`、状态、`v/w`、速度。

当前固件调试入口：

```text
line                     # 默认 0.18 m/s，持续循迹，直到 stop
line,0.12                # 0.12 m/s 低速循迹
line,0.18,1.20           # 循迹 1.20 m 后自动停车
stop                     # 手动停止
```

串口状态行关键字段：

- `mode=LINE`
- `state=ARC / ARC_L / ARC_R`
- `dist=<当前距离>/<目标距离>`，目标距离为 0 表示不按距离自动停车
- `line=<7路位型>`
- `bits/det/pos`
- `vw=(v,w)`

暂不要求：

- A/B/C/D 点自动判定。
- 任务 2/3/4 路线切换。
- 无线区和有线区自动融合。

## 8. 后续组合路线思路

当无循迹直线跑和有线循迹分别稳定后，再进入赛题组合。

推荐组合顺序：

1. 任务 1：A -> B，先用无循迹直线完成。
2. 右侧半圆：B -> C，单独用循迹调通。
3. 下方直线：C -> D，先用无循迹直线或速度开环直线。
4. 左侧半圆：D -> A，单独用循迹调通。
5. 任务 2：直线 + 右弧 + 直线 + 左弧。
6. 任务 3：斜线 + 右弧 + 斜线 + 左弧。
7. 任务 4：任务 3 连续 4 圈，加入圈数统计和速度优化。

## 9. 调试记录模板

每次实车测试建议记录：

- 日期与固件提交号
- 电池电压或电量状态
- 轮径参数
- 速度 PID 参数
- 航向 PID 参数
- 线位置 PID 参数
- 前进速度
- 测试路线
- 成功/失败现象
- 串口日志文件
- 需要修改的参数或代码

示例：

```text
date:
commit:
test:
route:
v_mps:
wheel_pid:
yaw_pid:
line_pid:
result:
issue:
next_action:
```
