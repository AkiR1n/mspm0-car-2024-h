# IMU 圆弧端点判定 TODO

## 背景

H 题场地只有两条黑色半圆弧，A/B/C/D 是圆弧端点，不是独立标记。

因此，线阵“居中”只能说明小车仍在圆弧线上，不能说明已经到达端点。之前在 D-A 尾段使用“中间三路线居中即停车”会导致未到 A 点提前停止。

## 当前采用方案

先在当前分支实现局部方案 2：IMU 半圆完成 + 端点丢线 + 小补偿停车。

传感器职责：

- 线阵：圆弧段横向贴线，不负责单独判断端点。
- IMU：记录进入圆弧时的 yaw，用 yaw delta 判断半圆进度。
- 编码器：仅作为距离门限和超程保护，不参与方向控制。

## D-A -> A 停车判定

1. 进入 D-A 圆弧时记录 `arc_entry_yaw_deg`。
2. 圆弧中继续使用线阵循迹。
3. D-A 尾段降速，减少冲出端点。
4. 只有满足以下条件后，才认为接近 A 点：
   - 当前阶段是最终 `ARC_DA -> STOP_A`。
   - 编码器距离超过最小端点窗口。
   - 线阵已连续丢线一小段时间。
   - IMU yaw delta 接近 180 度，或距离超过保护上限。
5. 进入最终补偿段：
   - 继续低速前进几厘米，让车身投影覆盖 A 点。
   - 只做弱 IMU 保向，避免尾段大幅横向修正。
6. 补偿距离达到后停车。

## 调试关注项

- 如果仍提前停：提高 `MAIN_FINAL_A_EXIT_MIN_DISTANCE_M` 或提高 yaw delta 门限。
- 如果过 A 点太多：降低 `MAIN_FINAL_A_COMPENSATE_DISTANCE_M`。
- 如果最后车头右偏：降低 `MAIN_FINAL_A_ALIGN_W_LIMIT_RADPS`。
- 如果到 A 点前丢线但不进入补偿：降低 `MAIN_FINAL_A_EXIT_YAW_MIN_DEG`。

## 后续方案 3

后续可把同样思想推广到完整场地模型：

- 每个直线段使用 IMU 保向 + 编码器距离。
- 每个圆弧段使用线阵贴线 + IMU yaw delta 判断半圆进度。
- 每个点位事件由几何进度、线状态、yaw 共同确认。
- Web dashboard 显示各阶段的 exit gate 条件，方便现场调试。
